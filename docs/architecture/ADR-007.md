# ADR-007: Untrusted-document pipeline (validation + sandboxed extraction)

**Status:** Accepted (Phase 4)

## Context
Resumes arrive as PDF or DOCX, complex formats whose parsers have a history of hangs,
memory blow-ups and exploits. Files can carry JavaScript, macros, embedded objects,
remote templates or zip bombs. External job-board content (HTML, URLs) is also untrusted.

## Decision
1. **Validate before parsing** (`documents/validation.py`):
   - size limit
   - type taken from magic bytes and cross-checked with the extension (the browser's
     MIME type is advisory)
   - page limit
   - reject PDF JavaScript, launch actions, embedded files and XFA
   - reject DOCX macros, ActiveX, OLE objects, remote templates and zip bombs
2. **Optional antivirus** (`documents/scanner.py`): ClamAV over clamd. It fails closed
   when it is configured but unreachable.
3. **Sandboxed extraction** (`documents/sandbox.py`): text is extracted in a child
   process with address-space and CPU limits, few file descriptors and no core dumps,
   killed on timeout. Encrypted PDFs are refused.
4. **Storage:** files are stored under generated keys, either on local disk or in a
   private Supabase bucket behind the `storage/` interface. Downloads go through the API
   as attachments.
5. **External content:**
   - Job HTML is converted to plain text in the backend (`connectors/normalize.py`).
   - The frontend renders job and resume text as text, never as HTML.
   - Only http(s) URLs are linked (`safeUrl`); connectors reject postings with other
     URL schemes.

## Consequences
- A hostile upload cannot take down the API process or execute content.
  `tests/fixtures/documents.py` generates hostile samples for the tests.
- Some legitimate but unusual files (encrypted PDFs, resumes with embedded objects) are
  refused, and the user must re-export them.
- The sandbox relies on POSIX resource limits. Behaviour on non-Linux hosts is
  best-effort.
