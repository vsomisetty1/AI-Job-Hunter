# ADR-014: Application automation runs in approval mode, by meaning, with checkpoints

**Status:** Accepted (Phase 8)

## Context
An approved package (ADR-012) still has to reach the employer through the ATS's own web
form. Forms differ per platform and per company, change without notice, and include
questions no profile can answer (consent, self-identification, anti-bot puzzles). A wrong
submission cannot be taken back; a duplicate one looks careless. Checked on live
Greenhouse, Lever and Ashby forms on 2026-11-27 (see docs/AUTOMATION_VALIDATION.md).

## Decision
- **Approval mode only.** Agent 10 prepares the form and stops; the user reviews it and
  confirms. The API accepts a submit only as `{"confirm": true}` while the filled form is
  open, after re-validating it. The database enforces it as well:
  `application_submissions.mode` may only be `APPROVAL_MODE`, and a row cannot be
  `submitting`/`submitted` without `confirmed_at`. Autonomous mode is a later, separate
  decision.
- **Fields by meaning, not selectors.** An in-page script describes every control from its
  labels (aria-labelledby, aria-label, `<label>`, legend, the text since the previous
  control, placeholder) and tags it with a run-time `data-ajh` handle; the filler addresses
  only that handle. A pure matcher (`field_matcher`) maps fields to facts by concept
  (names, contact, links, education, work authorization, sponsorship, years, salary, how
  you heard) and picks options by meaning (Yes/No, "CA" = "California", "B.S." =
  "Bachelor's Degree", year ranges). Every write is read back.
- **Never guess.** No fact, no answer: such fields are listed for the user. Package
  answers still marked "needs review" are never typed. Consent and certification boxes are
  never ticked. Voluntary self-identification is declined when the form offers it,
  otherwise left blank. Short facts (name, company, location) never answer long yes/no
  questions that happen to mention them.
- **Platform adapters stay thin**: where the form lives (Greenhouse's embeddable form works
  for every board, including those that redirect to a company site), how to reveal it,
  Lever's location suggestions and resume parsing, submit button, confirmation text.
- **Uploads first**, then a wait for sites that parse the resume (Lever), then answers, so
  the site's own parse never overwrites them. Up to three passes catch follow-up questions
  revealed by answers; a reload mid-fill restarts filling.
- **Checkpoints and recovery.** Each step records a checkpoint (field outcomes, uploads,
  form signature); the user's edits are stored separately and always win. Retry reopens
  the form and replays the decisions. Crashes, timeouts and network errors retry
  automatically (AUTOMATION_MAX_ATTEMPTS); closed jobs, changed forms and refused uploads
  stop with a reason. A submission is never retried automatically: no confirmation means
  `unconfirmed`, and the user checks before trying again. At startup, runs cut off by a
  restart are failed with the reason.
- **One Chromium per process**, a context per run (cookies persisted per platform in
  `browser_sessions`), at most AUTOMATION_MAX_SESSIONS open forms waiting for review,
  closed after AUTOMATION_SESSION_IDLE_MINUTES.
- **Evidence**: screenshots (stored under `automation/`, kept with their run), structured
  `automation_logs`, application events, and an `agent_runs` row per prepare.

## Consequences
- Some sites store an attached file as soon as it is attached (Greenhouse and Ashby upload
  to their storage before submit). Filling a form therefore shares the documents with that
  company's ATS even if the user cancels; the review screen and docs say so.
- CAPTCHAs need a visible browser (AUTOMATION_HEADLESS=false); headless runs report them.
- The open form lives in memory: a restart or idle timeout closes it, and the user retries
  (the checkpoint makes that quick). One worker only, like the scheduler (ADR-005).
- Location autocompletes call third-party services; when those fail, the field is left for
  the user.
- Workday and other platforms need their own adapter; the engine is shared.
