# ADR-004: Single-user, local-first security model

**Status:** Accepted (Phase 3)

## Context
The app is personal: one owner, running on their own machine, not deployed publicly. A
full user system would be dead weight. But an unauthenticated API reachable from the
network would expose resumes and could trigger applications.

## Decision
- There is exactly one principal, the owner. `core/security.get_current_user` decides
  only whether a request may act as the owner:
  - `AUTH_MODE=none` (default): no credentials, **allowed only when `BACKEND_HOST` is a
    loopback address**. The config refuses to start otherwise.
  - `AUTH_MODE=api_key`: `X-API-Key` or `Authorization: Bearer`, with a key of at least
    32 characters.
- The backend binds to `127.0.0.1` by default. CORS is limited to configured origins,
  without credentials.
- Every versioned route depends on `get_current_user`; only `/health*` is
  unauthenticated.

## Consequences
- Running locally needs zero setup, and a misconfiguration (open host with no auth)
  fails at startup instead of silently exposing the API.
- Going public later needs a new decision: real auth (e.g. Supabase Auth JWTs as another
  branch in `get_current_user`), rate limiting, and a review of what the API exposes.
- No per-user data partitioning exists. Every table is the owner's.
