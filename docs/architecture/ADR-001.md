# ADR-001: Modular monolith with enforced layers

**Status:** Accepted (Phase 1, enforced since the Phase 4 audit)

## Context
A single developer builds the app for one user. It has many concerns (resume parsing,
LLM calls, job boards, browser automation, scheduling) but low traffic. Microservices would
add deployment and consistency cost for no benefit. Without structure, however, a monolith
drifts into a tangle: routers querying the database, agents importing routers, import
cycles.

## Decision
- One FastAPI backend process plus one Next.js frontend.
- The backend is split into packages ordered in layers. Imports only point to the same
  or a lower layer:

| Layer | Packages |
|---|---|
| 8 | `main`, `bootstrap`, `__main__` (composition root) |
| 7 | `routers`, `dependencies` |
| 6 | `scheduler` |
| 5 | `services`, `learning` |
| 4 | `agents` |
| 3 | `repositories` |
| 2 | `connectors`, `documents`, `parsing`, `llm`, `storage`, `automation` (adapters) |
| 1 | `core` |
| 0 | `models`, `schemas`, `utils` |

- `bootstrap.init_services` builds long-lived objects (LLM client, storage, HTTP fetcher,
  connectors, discovery service) and stores them on `app.state`.
- Routers receive services through `dependencies.py`.

## Consequences
- `tests/unit/test_architecture.py` fails CI on an upward import or a package cycle,
  and checks that every module imports on its own.
- Provider logic stays in adapters. For example, connectors return `NormalizedJob`, and
  services never see platform JSON.
- Moving a piece out into its own service later means cutting along an existing layer
  boundary.
- It costs some indirection: a repository may not return agent types, so services
  convert between them (e.g. `JobRepository.existing_for_company` returns tuples).
